Claude AI Agent Framework Guide

A portable .claude/ framework that makes Claude Code project-aware, evidence-driven and gated at every quality step, from idea and spec to reviewed commit and pull request. This page is the map; each topic links to its owner doc.

    Critical rules

    Route first

    The first task of a session is routed (direct, custom-simple or a workflow) before any edit. Mid-session, never auto-start a workflow.

    Evidence, not memory

    Project facts come from the project config and reference docs. Cite file:line; below 80% confidence, don't act.

    Gates always run

    Root cause before a fix, a verdict before editing a failed test, review before commit, spec/doc sync when behavior changes.

    .claude/ is the source

    Mirrors for Codex and OpenCode, AGENTS.md and generated CLAUDE.md blocks are projections. Fix the source and regenerate.

    What the framework is

    A plain agent is capable but forgetful, confident without evidence and unaware of your project. Each layer here removes one of those failure modes.

    Routing — how a request becomes a route

    The workflow route is delivered only by hooks at prompt time (the gate and the workflow catalog as two hook outputs, in each person's mode: ask, auto or off); no tracked file carries it.

    1. Honor explicit requestsA /skill, /workflow-* or "use a workflow" always runs.
    2. AssessScope, change type, risk, ambiguity and needed artifacts. Escalate on risk and ambiguity, not file count.
    3. Pick a routeTrivial → direct · one module → custom-simple · non-trivial bug → workflow-bugfix · cross-module feature → workflow-feature.
    4. Check catalog fitKeep a workflow only if more than 80% of its unconditional steps do real work. A downgrade still keeps test, review, root cause and spec sync where they apply.
    5. Declare, ask, then activateRoute: workflow-bugfix — because … before any edit, agent or command. A matched workflow first asks one question: full workflow, slimmer custom route, or direct.

    auto

    Asks first; recommends the full workflow when it fits the request. Default when a workflow sets no tier.

    confirm

    Asks first; recommends the full workflow only when no leaner route would do the job.

    manual

    Asks first and never recommends the full workflow; it runs when you pick it. Set per project.

    Tune tiers with portability.workflowActivation (a default only tightens; an overrides entry may loosen). Set the route mode (ask, auto, off) with portability.workflowRouteMode; a person overrides it in ~/.claude/.ck.json, .claude/.ck.local.json or CK_WORKFLOW_ROUTE_MODE.

    Workflows — guided, gated execution

    A workflow is an intent, a set of outcome gates and an ordered list of steps. Each step has a role.

    gate

    Always runs. Never skipped, merged or reordered.

    core

    Recommended. May flex with a logged reason while the outcome gates stay reachable.

    optional

    Carries a written when and skip reason; skipped when the rule says it doesn't apply.

    How a run works

    1. TriageSize (XS to XL), change kinds and risk decide the depth.
    2. Read the guide, create phase tasksOne task per phase, titled [Workflow] [Phase 1/5: Discover] …, with a row per step showing its role, all before the first starts.
    3. Run, logging every deviationSkips go to tmp/workflow-runs/<runId>/skips.md with evidence; a task is never deleted. Parallel groups run as one wave and wait for every member.
    4. Close on evidenceworkflow-end refuses to close until each outcome gate (root cause traced, plan approved, tests pass, spec synced, review converged) has evidence.
    Nested workflowsRun as sub-agents that return a summary — except workflow-review-changes, which always runs inline so its review loop can hold the session open until it converges.

    skillProfile preset full · standard · minimal, plus nameOnly, commandOnly, off. Applied by sync-skill-profile.cjs; hiding a skill a workflow calls is refused.

    Review modes

    --fix-loop reviews, validates, fixes and re-reviews until converged. --report-only is a silent leaf reviewer for a caller that owns the fixes.

    Routing injection

    Gate and workflow catalog as two hook outputs, each once per session; re-armed on change, compaction or long growth.

    Protocol delivery

    A loading skill's protocols arrive in full, once per session, grouped and size-capped.

    File conventions

    Touching a file injects its path rules (opt-in). Shell read: file-conventions.cjs --lookup <path>.

    Prompt ledger

    Pins the session goal and every prompt in tmp/prompt-ledger/; re-delivered after compaction.

    Token checkpoint

    An advisory note each 500,000 non-cached tokens (configurable).

    Code graph · alerts

    Graph is auto by default (on only when built). Desktop alerts on; Discord, Slack, Telegram by env key.

    Shared protocols — one source, hybrid delivery

    About 98 reusable rules are written once as SYNC:<tag> blocks in .claude/skills/shared/sync-inline-versions.md and projected into shared/protocols/.

    CarrierHolds

    The quality chain — review, commit, pull request

    1. ReviewTriage all changes and create review tasks first. Standalone reviews default to review-only; the review workflow defaults to fix-loop. Every applied fix needs fresh review; LOW may be deferred without edits. Default cap three rounds; LOW-only at the cap is acceptable, while Critical/High/Medium or failed required checks ask the user for a bounded extension.
    2. Validate findingswhy-review --validate-findings checks each finding against evidence before any fix, and never recurses.
    3. Fix at the ownerfix --target=review records FIXED / REJECTED / DEFERRED; an unexplained defect is traced first.
    4. ReceiptA converged fix-loop mints a receipt for that exact changeset; any later edit invalidates it.
    5. Commit/commit decides the test and review gates by risk without asking; the commit gate blocks any agent commit without a receipt.
    6. Pull request/pull-request decides tests and the whole-branch review by risk without asking, runs the selected gates, commits, pushes, opens a ready PR and fixes CI until green. It never merges; it force-pushes only its own rebased PR branch, with an explicit lease, when pullRequest.pushedBranchUpdate is rebase.
    Git disciplineNever commit, push or stage without an explicit request; branch first on the default branch; never destroy uncommitted work without asking; treat gh writes like a push. Only the literal permissions.ask patterns still prompt; the commit review gate is the one mechanical rule.

    Design and UX gates

    Any task that creates or reshapes a screen runs three rule sets in order, then a review procedure.

    1. UX-1–UX-11journeys first
    2. UI-1.1–UI-9.4usability floor
    3. DD-1–DD-8product identity
    4. CL-1–CL-6review procedure

    Journey report first

    Who uses the screen, their job, the ranked main journeys and each journey's steps — before any mockup or UI code. It ends with a pass/fail gate report.

    Explore mode

    Asks for 3, 2, 1 drafts or skip; opens drafts in the browser; recommends one with evidence; builds only the chosen direction.

    Precedence

    Your brief → the project's design system and ADRs → these clauses. Genuine conflicts go to you.

    Specs and tests

    Specs

    Portable default: an 8-section Feature Spec with test cases TC-{FEATURE}-{NNN} in §8; projects may declare their own profile. spec authors, amends, writes test specs and syncs.

    Tests verify intent

    Each test names the rule it protects and must fail when that rule breaks.

    A failed test gets a verdict first

    Source wrong · test wrong · test not optimal · environment blocked · ambiguous. Never weaken a test to force green.

    Principles

    Evidence before conclusion

    Cite file:line, state confidence, don't recommend below 60%.

    Root cause at the owner

    Trace the wrong state to the component that owns the invariant; fix once there.

    Judgement integrity

    Treat a prompt's premise as a hypothesis; test it and its opposite. "No issues" is a valid verdict.

    Hooks deliver the contract

    Universal rules, route and overlay reminders arrive only through hooks; a host with no hooks is unsupported. An unreadable shipped file yields a one-line notice, and Codex needs the handlers reviewed in /hooks.

    Context is a budget

    Deliver rules once, when they apply; write long work to disk.

    Parallel when independent

    Tag tasks PAR or SEQ; run independent waves in one message and wait for all.
